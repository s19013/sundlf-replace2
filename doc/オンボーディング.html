1. このアプリは何か

Laravel(バックエンド)と Vue 3(フロントエンド)を組み合わせた、認証機能を持つ SPA(シングルページアプリケーション)の開発基盤です。 現状は認証(登録・ログイン・ログアウト・ユーザー取得)のみが実装済みで、その上に業務機能を積み上げていく前段階の状態です。

  • コア機能: Laravel Sanctum による SPA 認証(CSRF Cookie ベース)
  • API: dedoc/scramble による OpenAPI 仕様自動生成 + Ziggy によるルート共有
  • UI: Vue 3 + Pinia によるリアクティブな状態管理

5. 新規API追加フロー

.kiro/steering/structure.md に定義されている、新しいAPIを追加する際の標準手順です。

sequenceDiagram
    participant Dev as 開発者
    participant BE as backend/routes・Controller・Usecase
    participant Gen as mise generate:*
    participant FE as frontend/entities

    Dev->>BE: 1. routes/api.php にルート追加
    Dev->>BE: 2. Controller / Usecase 実装
    Dev->>Gen: 3. mise generate:ziggy
    Note right of Gen: backend→frontendへ
ziggy.js/ziggy.d.tsを配置
    Dev->>Gen: 4. mise generate:openapi
    Note right of Gen: scramble:export→
openapi-typescriptでschema.d.ts生成
    Dev->>FE: 5. entities/[domain]/api にAPI関数追加
順序が重要: ルートやレスポンス定義を変更したら、フロント実装前に必ず mise generate:ziggy → mise generate:openapi の順で実行してください (lefthookのpre-commitでもある程度自動実行されますが、開発中は手動実行が必要です)。

7. Kiroスペック駆動開発の状況

このプロジェクトは .kiro/ によるスペック駆動開発(要件→設計→タスク→実装)を採用しています。 現在 .kiro/specs/ に存在するのは register スペックのみです。

Spec名フェーズ要件設計タスク実装

register スペックは要件定義から実装まで完了しています。 次に新しい機能を作る場合は、このスペックを型として /kiro:spec-init "説明" から始めるのがこのプロジェクトの流儀です。

.kiro/steering/ には product.md(プロダクト概要)・tech.md(技術スタック)・structure.md(構成パターン)の3ファイルがあり、いずれもカスタム追加なしのデフォルト構成です。困ったらまずこの3ファイルを読むと全体像が分かります。
