# カラム

| カラム名   | ラベル   | 型                  | nullable | デフォルト値 | インデックス | 備考                          |
| ---------- | -------- | ------------------- | -------- | ------------ | ------------ | ----------------------------- |
| tag_id     | タグID   | bigint(20) UNSIGNED | false    |              | true         | 主キー、外部キー（`tags.id`） |
| count      | 使用回数 | bigint(20) UNSIGNED | false    | 0            | false        | 紐づくメモ・ブックマークの数  |
| created_at | 作成日時 | timestamp           | true     | NULL         | false        |                               |

タグ（[`tags.md`](./tags.md)）のうち、ユーザーが直接変更しない項目を管理するテーブル。

# リレーション

## tag_id

`tags.id` を参照する外部キー。1つのタグに対して1行だけ存在する（1対1）。

# 制約

## tag_id

主キー制約。1つのタグに対して status の行が複数作られないようにする。

外部キー制約（`tag_statuses_tag_id_foreign`）。`ON DELETE CASCADE` のため、参照先のタグが削除されると、このテーブルの行も削除される。

# 備考

## 分離した理由

[`article_statuses.md`](./article_statuses.md)の「分離した理由」と同じ。
タグの `count` を `tags` に置いていたときは、増減のたびに `tags.updated_at` まで更新され、タグ検索の更新日順に影響していた（#122）。

## 行の作成・削除

- タグ作成時に、同じトランザクション内でこのテーブルの行も作成する。
- タグが削除されたときに CASCADE で削除される（タグは物理削除のみ）。

## 既存データの移行

移行時に、`tags` の `count` の値を使って全タグ分の行を作成する。その後、`tags` から `count` カラムを削除する。
