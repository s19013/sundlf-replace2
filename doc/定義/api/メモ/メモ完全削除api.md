# api名

memos.complete-deletion

# 概要

このAPIは**論理削除された**メモ完全削除を行います。

# エンドポイント

delete `/api/memos/{id}/completely`

# 認証

必須

# パスパラメータ

最新の詳細な型はscramble生成のOpenAPI/schema.d.ts参照

| 名前 | 型     | 必須 | 説明   |
| ---- | ------ | ---- | ------ |
| id   | string | yes  | メモID |

# レスポンス

ステータスコード:200

```json
{
  "messages": ["{タイトル名}を完全削除しました。"]
}
```

# バリデーション

id:['required', 'integer']

# 処理の流れ

- バリデーションチェック
- メモ情報取得(論理削除されたメモも対象)
- メモの作成者idとログイン者のid確認
- メモが論理削除状態か確かめる
- `DB::transaction`内で以下をまとめて実行する
  - 対象メモを行ロック(`lockForUpdate`)して再取得
    - 既に物理削除されていた、または論理削除状態でなくなっていた場合(同時実行で復元された場合など)は、何もせずに終了する
  - 削除処理(物理削除)
    - 中間テーブル(`article_tags`)のデータは、DBの外部キー制約(`ON DELETE CASCADE`)により自動的に削除される
- レスポンス返却

# エラー

## メモが取得できなかった

物理削除済みなど

ステータスコード:404

```json
{
  "messages": ["メモが見つかりませんでした。"]
}
```

## メモの作成者とログイン者のidが違う

他人のメモの存在を推測できないようにするため、403ではなく404を返す。

ステータスコード:404

```json
{
  "messages": ["このメモは完全削除できません。"]
}
```

## 対象が論理削除状態ではなかった

ステータスコード 422

```json
{
  "messages": ["ゴミ箱にないメモは完全削除できません。"]
}
```

# 備考

- タグの使用回数(`count`)はこの処理では変化しない。論理削除時に既に減算済みのため(`メモ削除api.md`参照)。
