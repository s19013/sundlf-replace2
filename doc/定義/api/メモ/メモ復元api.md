# api名

memos.salvage

# 概要

このAPIは論理削除されたメモを復元します。

# エンドポイント

post `/api/memos/{id}/salvage`

# 認証

必須

# パスパラメータ

最新の詳細な型はscramble生成のOpenAPI/schema.d.ts参照

| 名前 | 型     | 必須 | 説明   |
| ---- | ------ | ---- | ------ |
| id   | string | yes  | メモID |

# レスポンス

ステータスコード:200

```json
{
  "messages": ["{タイトル名} を復元しました。"]
}
```

# バリデーション

id:['required', 'integer']

# 処理の流れ

- メモ取得(論理削除されたメモも対象)
- メモの作成者idとログイン者のid確認
- メモが論理削除状態か確かめる
- `DB::transaction`内で以下をまとめて実行する
  - 対象メモを行ロック(`lockForUpdate`)して再取得
    - 既に物理削除されていた、または論理削除状態でなくなっていた場合(同時実行で先に復元された場合など)は、何もせずに終了する
  - 紐付いているタグの使用回数(`count`)を加算
  - 復元作業(`deleted_at`をnullにする)
- レスポンス返却

# エラー

## メモが取得できなかった

物理削除済みなど

ステータスコード:404

```json
{
  "messages": ["メモが見つかりませんでした。"]
}
```

## メモの作成者とログイン者のidが違う

他人のメモの存在を推測できないようにするため、403ではなく404を返す。

ステータスコード:404

```json
{
  "messages": ["このメモは復元できません。"]
}
```

## 対象が論理削除状態ではなかった

ステータスコード 422

```json
{
  "messages": ["ゴミ箱にないメモは復元できません。"]
}
```

# 備考

- 論理削除時に減算したタグの使用回数(`count`)を、復元時に加算して元に戻す(`メモ削除api.md`参照)。
- 行ロック後に再確認するのは、同時に復元リクエストが来た場合にタグの使用回数が二重に加算されることを防ぐため。
