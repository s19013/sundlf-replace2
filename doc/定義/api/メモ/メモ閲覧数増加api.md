# api名

memos.view-count.increase

# 概要

このAPIは対象のメモの閲覧数を1増やします。

# エンドポイント

post `/api/memos/view-count/increase/{id}`

# 認証

必須

# パスパラメータ

最新の詳細な型はscramble生成のOpenAPI/schema.d.ts参照

| 名前 | 型     | 必須 | 説明   |
| ---- | ------ | ---- | ------ |
| id   | string | yes  | メモID |

※ URLのパスパラメータのため型はstring。数値形式であることはバリデーション(`integer`)で検証する。

# レスポンス

ステータスコード:200

# バリデーション

id:['required', 'integer']

# 処理の流れ

- メモ取得
- メモの作成者idとログイン者のid確認
- 閲覧数増加処理(`article_statuses.count` を +1)

# エラー

## メモが取得できなかった

論理削除済み、物理削除済みなど

ステータスコード:404

```json
{
  "messages": ["メモが見つかりませんでした。"]
}
```

## メモの作成者とログイン者のidが違う

他人のメモの存在を推測できないようにするため、403ではなく404を返す。本文も「メモが取得できなかった」場合と同一にする。

ステータスコード:404

```json
{
  "messages": ["メモが見つかりませんでした。"]
}
```

# 備考

- 閲覧数(`count`)は`article_statuses`で管理しているため、加算しても`articles.updated_at`は変わらない。検索での更新日順ソートや、楽観的排他制御(`fetched_at`との比較)に影響を与えない。

## なぜ個別に増加apiを設けるのか

取得apiは、更新画面でも元のデータを取得するために使う。
カウントを取得apiに含めてしまうと、更新時にもcountが増加してしまう。
